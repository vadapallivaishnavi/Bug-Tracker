1. What you are installing

OSDBcortex is a PostgreSQL monitoring and AI-assisted database administration platform. It has four parts:

ComponentWhat it does
CollectorCollects metrics from PostgreSQL system views.
ServerThe MCP API server (backend, port 8080).
AlerterMonitors collected metrics and raises alerts.
ClientThe web dashboard you open in a browser (port 3000).

All components share one central PostgreSQL database. The installer scripts set up the database, the systemd services, and a reverse proxy for the web client automatically.

2. Before you start

You need the following:

  • A Linux server. Both installers support Ubuntu 20.04+ and RHEL 8+.
  • A user with sudo access.
  • Internet access on the server (unless you use the offline Path C option).
  • A copy of the OSDBcortex repository on the server, or the pre-built offline bundle for air-gapped servers.

To get the repository on your server:

git clone https://github.com/osdbcortex/osdbcortex.git
cd osdbcortex

The two installers live in the scripts/ folder.

3. Which script should I use?

Answer these three questions to choose the right script:

Your situationRecommended scriptWhy
You want a fresh server installed with one command, and you are happy with the default layout. scripts/install.sh Builds everything and configures PostgreSQL, systemd, and nginx for you automatically.
You want to choose a deployment style: Docker, native, or offline. scripts/deploy.sh An interactive wizard that asks questions and lets you pick a deployment path (A, B, or C).
You want the same wizard but from scripts or CI, without prompts. scripts/deploy-wizard.sh The same engine as deploy.sh, with command-line flags and a --non-interactive mode.
Your server has no internet access (air-gapped). deploy.sh --path C-create then --path C-deploy Creates an offline bundle on a connected machine and installs it on the isolated one.

If you are still unsure, start with scripts/install.sh. It is the most automated and beginner-friendly.

4. Option A: One-command install with install.sh

The install.sh script installs OSDBcortex on a bare server. It detects the operating system, installs Go, Node.js, nginx, and the build tools if they are missing, then builds all components and starts the services.

4.1 Steps

1 Clone the repository and enter the scripts/ directory. 
git clone https://github.com/osdbcortex/osdbcortex.git
cd osdbcortex/scripts
2 Run the installer as root with the interactive prompt. 
sudo ./install.sh

The script asks you for a PostgreSQL password and then does everything else on its own. Installation takes several minutes because it compiles from source.

3 Wait for the final Installation Complete message, then continue to After installation.

If you prefer to supply values up front, pass them as flags:

sudo ./install.sh \
  --pg-database osdbcortex \
  --pg-user osdbcortex \
  --pg-password 'YourStrongPassword' \
  --server-port 8080 \
  --client-port 3000

4.3 Uninstalling

To remove everything that install.sh created:

sudo ./install.sh --uninstall

The script stops and removes the services, configuration, and the system user. It does not drop the PostgreSQL database by default; the script tells you the command to drop it if you want.

5. Option B: Guided wizard with deploy.sh

The deploy.sh wizard walks you through the installation with questions. It supports three deployment paths:

PathNameBest for
ADocker Compose (online)The quickest setup; everything runs in containers.
BDirect VM / systemdNative binaries installed directly on the host.
CAir-gapped / offlineServers with no internet access.

5.1 Path A - Docker (easiest)

Path A deploys all components with Docker Compose. It needs Docker and Docker Compose v2 installed.

1 Start the wizard and choose A when asked, or pass it directly. 
bash scripts/deploy.sh --path A
2 Follow the prompts. You will be asked for a PostgreSQL password. You can also export it first: 
export POSTGRES_PASSWORD='YourStrongPassword'
bash scripts/deploy.sh --path A --non-interactive --install-prereqs auto

After it finishes, the client is available at http://<server-ip>:3000 and the server API at http://<server-ip>:8080.

5.2 Path B - Native VM / systemd

Path B installs native Go binaries and the web client directly on the host, creates a dedicated service user, registers systemd units, and optionally configures nginx.

1 Run the wizard and choose B. 
bash scripts/deploy.sh --path B
2 Answer the prompts about PostgreSQL, ports, nginx, and systemd. For an unattended install use the wizard variant: 
bash scripts/deploy-wizard.sh --path B --non-interactive \
  --postgres-password 'YourStrongPassword' \
  --configure-postgres yes \
  --install-nginx yes

Binaries go to /opt/osdbcortex/bin, configuration to /etc/osdbcortex, and the services run as the osdbcortex user.

5.3 Path C - Offline / air-gapped

Path C has two phases: create the bundle on a machine with internet, then deploy it on the isolated server.

1 On a connected machine, create the offline bundle. 
bash scripts/deploy.sh --path C-create

Or with the wizard:

bash scripts/deploy-wizard.sh --path C --offline-action create --non-interactive \
  --client-source dist

This produces a .tar.gz archive containing the binaries, client, configuration templates, and systemd units.

2 Copy the bundle archive to the isolated server, for example with scp or a USB drive.
3 On the isolated server, deploy the bundle. 
bash scripts/deploy.sh --path C-deploy

Or with the wizard:

bash scripts/deploy-wizard.sh --path C --offline-action deploy --non-interactive \
  --bundle-archive /tmp/osdbcortex-offline-bundle.tar.gz \
  --postgres-password 'YourStrongPassword'

The deploy step extracts the bundle, installs the binaries and services, and prepares the PostgreSQL role and database.

6. After installation

Once the installer finishes, verify the services are running:

systemctl status osdbcortex-collector osdbcortex-server osdbcortex-alerter

Then open the web client in your browser:

ServiceAddressPort
Web client (dashboard)http://<server-ip>3000
Server APIhttp://<server-ip>8080
PostgreSQLlocalhost5432

Useful commands for day-to-day operation:

# View logs
sudo journalctl -u osdbcortex-server -f
sudo journalctl -u osdbcortex-collector -f
sudo journalctl -u osdbcortex-alerter -f

# Restart a service
sudo systemctl restart osdbcortex-server

7. Troubleshooting

ProblemFix
cp: cannot stat '...systemd/osdbcortex-collector.service' Your offline bundle was created by an older version of deploy.sh that named the units osdbcortex-*.service. Update deploy.sh and re-create the bundle, or re-run the deploy step with the fixed script.
docker: command not found (Path A) Install Docker, then re-run with --install-prereqs auto.
PostgreSQL connection refused Ensure PostgreSQL is running: sudo systemctl start postgresql, and that the osdbcortex role and database exist.
Client page does not load Check nginx: sudo systemctl status nginx and the port in the configuration.
A service keeps restarting Check its log: sudo journalctl -u osdbcortex-server -f. A missing password file or wrong datastore credentials is the usual cause.
You are unsure what the script will do Run it with --dry-run first. Nothing is changed.

8. Important notes

Names are case-sensitive. Linux usernames and PostgreSQL roles and database names are case-sensitive. The deployment scripts use the lowercase name osdbcortex for the service user, PostgreSQL role, and database. If your system already has an uppercase osdbcortex user or role from a previous attempt, the scripts will not be able to reuse it; remove or rename it first.

Offline bundles must match the deploy script. The Path C bundle and the deploy step must come from the same version of the scripts. Mixing versions can cause missing files or case mismatches in systemd unit names.

Always use a strong, unique password for the PostgreSQL role. The deployment scripts store it in a root-owned password file, not inside the YAML configuration.
